# Changelog

All notable changes to claude-mcp-check are written here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [1.0.0] - 2026-10-16

- First release. A CLI and a Claude Code plugin with one user-only skill, `/mcp-check:check`.
- `show` lists every MCP server Claude Code would load for a project, from `--mcp-config` files, the project's entry in `~/.claude.json`, the `.mcp.json` of the folder and of every folder above it, `~/.claude.json` itself and the enabled plugins, with the file, the key and the line of each definition, the scope, the transport, the command or URL (credentials hidden), which definition wins when a name is defined twice, the approval of `.mcp.json` servers (approved, pending, rejected), whether the project switched a server off, whether `allowedMcpServers` or `deniedMcpServers` keep it out, and what `claude -p` does differently from a session.
- `check [name]` starts each stdio server with the command, arguments, environment and folder Claude Code would use, performs the MCP handshake, lists tools, resources and prompts, times the answer to `initialize`, and sizes the tool schemas (characters, and characters / 4 as a labelled estimate); an HTTP or SSE URL is probed and `needs login` is told from the status code, with no token read and no header sent unless `--send-headers`. Every process it starts is ended; a `.mcp.json` server nobody approved is not started unless `--include-unapproved`.
- `why <name>` names the cause: not approved, switched off, blocked by a list, an invalid definition, command not found, a `${VAR}` set nowhere or empty, non-JSON on stdout, an exit before the handshake (with the exit code and the end of stderr), no answer within the timeout (and what `MCP_TIMEOUT` is), needs login, and the HTTP failures.
- `lint` finds a name defined in two scopes, a command that is not on the PATH, a `${VAR}` set nowhere (and one that only a project or local settings file sets, which Claude Code does not use for `${VAR}`), a credential name that reads as empty in a remote server's headers, a `.mcp.json` server nobody approved, a server both enabled and disabled, a list key that holds a plain string (Claude Code before 2.1.299 ignores the whole settings file for it), a plain-http URL, an invalid file or entry that Claude Code skips without a word, names that share a tool prefix, and more. `lint --markdown` is the short report the skill hands to Claude.
- `toggle <name> --on|--off` writes `enabledMcpjsonServers` or `disabledMcpjsonServers` in `.claude/settings.local.json` for a `.mcp.json` server, and `disabledMcpServers` of the project in `~/.claude.json` (under the lock Claude Code uses) for any other; after a backup, with `--dry-run`, and `restore` puts the newest backup back.
- What Claude Code does is what the real binary did: `test/e2e-claude.test.mjs` puts the sources, the states, the expansion, the command lookup, the policy lists, the tools of a run and the toggles to Claude Code 2.1.295 and 2.1.299 on Windows, and the same checks run in CI on Linux and macOS (2.1.295, 2.1.299 and 2.1.301 were run there). The two systems differ in how a command written as one string is read (split on Windows, not on Linux and macOS) and in what a missing command is reported as; the tool follows each (README "What was verified").
- Zero tokens for the tool. The skill is user-only, adds nothing to a request that does not use it, and hands the model a report of at most 12 findings.
